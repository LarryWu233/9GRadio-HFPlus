# AM detector boundary

AM remains one `DemodMode.AM`; `AmSettings.detector` selects envelope, SAM DSB, SAM USB or SAM LSB. These do not replace ordinary suppressed-carrier USB/LSB modes. Existing station/monitor memory remains keyed by AM.

`AmProcessor` in `radio-core` is a serial, closeable selected-channel IQ → mono PCM port. It receives explicit sample rate, RF bandwidth, immutable AM settings and the independently measured channel level. `ChannelProcessor` owns channel filtering/resampling and the detector lifetime; `NativeAmProcessor` owns the JNI handle. No detector creates queues, USB controls, AudioTrack, UI or map objects. Published PCM still gets the receiver's normal owned `AudioBlock` metadata and generation handling.

The AM channel passes symmetrically filtered complex IQ to the detector so a one-sided detector retains its carrier reference. Single-sideband selection happens inside the pinned WDSP kernel, not by treating SAM USB/LSB as ordinary suppressed-carrier demodulation. SQL and spectrum highlighting use the actual selected RF side. The wrapper maps WDSP's legacy allpass sideband numbering to the receiver's positive-frequency IQ convention; independent opposite-sideband stimuli cover this boundary.

Preview 19 adds the separate `ComplexChannelFilter` port before detection. `NativeChannelFilter` uses the existing FIR coefficient design and VOLK-derived dot product at the reduced channel rate, retaining source-rate anti-alias filtering. This gives a useful transition width against adjacent carriers without putting UI or output-device responsibilities into the detector. The 96-tap FIR retains overlap across blocks, resets with channel discontinuities/configuration, and operates in place only on channel-owned scratch. At 48 kHz its fixed group delay is about 0.99 ms; frame counts and raw-source timelines do not change. The new stage is not enabled in other demodulation modes.

Detector changes are serialized with IQ processing, establish an output configuration generation, clear pending old PCM and reset state at the normal discontinuity boundary. An explicit detector change joins and reopens the existing playback output: the tested platform returns zero on the first write after an active pause/flush. Continuous tuning and automatic lock/fallback transitions do not reopen playback. A stopped session closes its native state. The adapter observes carrier coherence/phase over 200 ms before declaring lock; a sustained bad state over 350 ms falls back to envelope through a 20 ms crossfade. This is an observation of the existing PLL, not a second control loop. Capture range is ±250 Hz.

For a future detector, implement `AmProcessor` (or extend the existing native adapter for an additional mature kernel), declare its rate/BW requirements and wire its choice/status at the application boundary. It should not require changes to source transport, recording, playback or decoder result destinations. This is explicit assembly, not automatic runtime plugin discovery.

AM audio filtering uses 90% of the available audio sideband, capped at 20 kHz and 45% of actual sample rate. Manual Audio BW can only narrow that bound. Switching symmetric ↔ single-sided AM preserves audio width by halving/doubling displayed RF BW; it leaves frequency, Step and AM station memory alone. Existing ACARS uses its previous envelope detector. DC suppression is bypassed near an AM/ACARS carrier at hardware center; away from the protection region the previous source DC filter remains available.

Carrier AGC is separate from RF hardware gain and listening loudness compensation. Slow/Fast/Off, maximum gain and low-level gain-hold policy are AM settings. The listening compensator is skipped while AM primary AGC runs, preserving its saved choice for other modes. NR/notch/SQL and voice recording keep their existing downstream routing. The retained tanh safety limiter exposes a cumulative trigger ratio; it is not presented as a new noise reduction algorithm.
