# Resume checklist after the nightly checkpoint

This records unfinished engineering and acceptance work. The nightly target of approximately 75% is an engineering estimate, not a claim that 75% of every test gate has passed or that the remaining elapsed time is proportional. The branch stays separate from main.

## Revised verification scope — user instruction on resumption

Verification is driven by an actual change, a reproduced defect or a genuinely new/unknown path. Do not add a broad suite merely to increase case counts. Keep useful existing checks; add only focused regression evidence for the behavior at risk. Estimates include implementation/debugging time and are not test-duration quotas.

- Reuse the recorded clock simulation, hardware and decoder results where the relevant behavior is unchanged. A pure extraction with output-equivalence evidence does not reset the entire hardware matrix.
- Compare a candidate only if there is a concrete reason to adopt it. Use short identical-input correctness/resource/CPU comparisons, retaining the agreed adoption thresholds. If benefit is unproven or integration is disproportionate, keep the current backend and document that decision; do not integrate every candidate just for evaluation.
- Hardware validation covers the affected connection, tune, mode and recording operations plus representative reception. Extend a run only to examine a specific suspected instability or an observed trend. Do not mechanically run every device/mode for 30 minutes, repeat already-valid long tests, or extend a stable run beyond roughly an hour without a reason.
- A new playback-clock/backend path requires its own focused validation. Unchanged UI, protocol algorithms and native components use existing evidence unless an affected boundary creates a specific regression risk. Static ABI/alignment and release privacy checks remain part of delivery.

The revised scope supersedes the blanket full-matrix/long-run wording below. Keep unresolved gates visible; do not substitute a smaller test count for evidence about an actual known problem.
