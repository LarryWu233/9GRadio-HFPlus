# 0.29.0 — AIS, microphone CW and SSTV gallery saving

Regular GitHub release requested by the user, built from `refactor/receiver-pipeline`. Main is not merged by this publication. The normal application ID remains `com.radiosport.ninegradio.hfplus`; existing HF+ application settings, databases and recordings are retained on upgrade. Architecture previews have their own directory and remain separate. Release assets contain only the installable APK; corresponding source, build instructions and dependency licences remain public at the release tag.

## Behavior

- AIS A/B uses pinned AIS-catcher on raw UInt8 or Float32 IQ, centered at 162 MHz. The Android source retains USB ownership. For the first live AIS selection, prefer an available 288 kS/s RTL or 768 kS/s HF+ rate; user-saved supported rates remain available. BW is decoder-managed. No monitoring, noise-reduction or AudioTrack path is opened for this data-only mode; IQ recording remains available.
- Vessel results include available MMSI, identity, position, speed, course/heading and position age. The existing map provider and shared table are reused. Ships follow valid received heading/course, use a distinct unknown-heading fallback and turn red after five minutes without a position update. Non-position identity messages do not freshen position age. Missing coordinates stay off the map but remain in the table. AIS distance records use a separate prefix from ADS-B.
- Raw decoder subscription precedes producer startup. File metadata establishes the initial demodulation mode before capture starts. Normal EOF waits for native decoder drain outside the serial control executor; timeout is reported. Stop still joins native work and invalidates old-session output.
- Microphone and WAV CW use the unmodified pinned ggmorse core for automatic tone and speed estimation, with existing fixed WPM choices. The old full-band magnitude detector has no tone selectivity, making it unsuitable as the sole detector for a noisy acoustic input. Software narrowband CW retains its current multimon path. This does not promise decoding of speech, multiple simultaneous Morse tones or arbitrary interference. Automatic pitch range is 200–1200 Hz and nominal automatic speed range is 5–55 WPM.
- Explicit SSTV/SAT image saving keeps app history and publishes PNG to the system gallery under `Pictures/9GRadio HF+`. Android 10+ uses MediaStore pending-write completion and removes failed media entries. App history remains available if gallery writing fails. Automatic reception history remains private until explicitly saved. The older Android storage-permission path is retained, but was not exercised on the available Android 13 device.
- ETM expanded viewport and EiBi frequency/time/location ranking from [preview 21](architecture-21.md) remain. Location ranks all active candidates without excluding distant transmitters.
- LRPT is deferred at the user's request. No LRPT registration, unfinished mode or SatDump/VOLK probe is included in the application.

## Evidence and limits

- 167 existing/focused JVM checks pass: 50 core and 117 app, no failures or skips. New checks cover AIS fields, input capabilities, map heading/staleness and CW backend selection.
- On the Android 13 backup device, the packaged AIS decoder accepts both input formats, reaches finite EOF without false targets, rejects an unsupported rate and releases busy pipes. Relevant existing Readsb stop/gap checks and geographic distance checks pass.
- Independent AIS reference: the public freerange Helsinki FM discriminator recording, SHA-256 `384b2183e41f4c6de5ca5df907bed40ec8fa547c70f076dee4190f2a69877b8e`. Direct FM reference decoding yields 89 messages for the selected 12 seconds. A documented test-only re-modulation yields 87 messages from 288 kS/s UInt8 and 88 from 768 kS/s Float32, ten distinct MMSIs each. The actual registered Android FileIqSource path passes both formats with at least 80 valid messages, at least eight targets, all input samples accounted for and no application/driver loss. These are IQ derivatives of an independent FM recording, **not captured raw RF**.
- Actual service/UI reference replay establishes AIS from a previously saved AM mode, fills the target table/map binding, keeps monitoring disabled and reports no input gap. Its private screenshot was checked. Initial UI attempts blocked by system lockscreen are not counted as passes. Online tile availability is separate from successful position decoding/binding and is not a new mainland-network certification.
- CW uses an independent ARRL 20 WPM publication, with a 35-second excerpt and a deterministic derived version containing broadband noise, low-frequency hum and delayed echo. The actual WAV/native adapter decodes the expected reference prefix in both. Clean synthetic fixed/automatic WPM tests also pass. A test initially detected the EOF silence clearing the displayed tone estimate; the adapter now preserves the last valid estimate at EOF. The user's specific microphone/speaker setup remains their requested follow-up check; acoustic reception was not claimed from a WAV run.
- Robot36 WAV reception reaches a complete image, the explicit save is indexed as a completed non-pending PNG in MediaStore and Android can reopen/decode it with the expected dimensions. Test-created media entries and files are removed. Related audio-content cancellation/lifetime checks pass.
- Initial minified Release instrumentation could not start because its precompiled test framework referenced runtime facades removed by R8. These attempts are not counted as passes. The first regular release preserves the validated unminified class graph and disables debugging; no test framework or special test-dependency keep rules are added to the app.
- A new native-gap check reproduced a retired reader's I/O exception cancelling its successor and leaving running status stale. Failure propagation now checks both session and run identity, just like results; current-session input failures publish a stopped/error state even while the native run is being replaced. The exact failing check passes for both IQ formats after the fix.
- No new numerical power-saving claim is made. Actual AIS RF reception, the user's acoustic CW setup, Android 16 follow-up and actual 16 KB runtime remain explicitly unverified for these new changes. Previous relevant architecture results are retained; this release does not claim all historical acceptance gates were rerun or closed. See [remaining architecture acceptance](remaining-acceptance.md).
